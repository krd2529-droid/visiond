# VSMS — Android v0.5.2

## เพิ่มใน 0.5.1

- ปุ่มเบอร์ที่สุ่มได้แสดงทุกเบอร์ในคิวพร้อมผลส่ง แตะดูรายละเอียด และกรองรายการสำเร็จในหน้าสถานะ
- เมื่อระบบรายงานส่งไม่สำเร็จครบทุกส่วน รอสุ่มจำนวนเต็ม 5–10 นาทีจากเวลาทราบผล แล้วส่งเบอร์ถัดไปที่ยังรอในคิวเดิม ไม่ส่งเบอร์ล้มเหลวซ้ำ ไม่เพิ่มจำนวนเบอร์เกินคิว เมื่อส่งสำเร็จยังรอ 10–30 นาทีตามเดิม หากกดหยุดจะไม่เริ่มเอง และเมื่อครบคิวจะหยุด
- กรณีไม่ได้รับผล/ไม่ทราบผลยังหยุดเพื่อตรวจสอบ ไม่ถือว่าส่งล้มเหลวโดยไม่มีหลักฐาน เวลาปลุกอาจเลื่อนจากที่ตั้งไว้เมื่อ Android จำกัด alarm ใน Doze
- บันทึกเฉพาะเบอร์และลิงก์ที่ส่งสำเร็จอัตโนมัติในไฟล์ส่วนตัว successful-sends.json แยกจากคิว เก็บต่อเนื่องเมื่อสร้างคิวใหม่ กดปุ่มบันทึกไฟล์เบอร์ + ลิงก์ที่ส่งสำเร็จ (CSV) เพื่อเลือกที่เก็บไฟล์ CSV ซึ่งรวมเวลาและผลยืนยันการรับ ลิงก์ตรงกับข้อความที่ส่ง ข้อมูลเดิมก่อนอัปเดตดึงได้เฉพาะคิวที่ยังเก็บอยู่
- ส่งสำเร็จ คือระบบรายงานส่งครบทุกส่วน; ถึงเครื่องผู้รับแล้ว คือรายงานเครือข่ายยืนยันการรับครบทุกส่วน; ไม่มีรายงานแสดงยังไม่ยืนยันการรับ SMS ไม่มีสถานะอ่านแล้ว ไม่อนุมานจากการคลิกลิงก์ รายงานรับรองรับคิวปัจจุบัน หากสร้างคิวใหม่ก่อนรายงานมาถึง รายงานของคิวเก่าจะไม่ถูกนำมาใช้
- API อ้างอิง: https://developer.android.com/reference/android/telephony/SmsManager
- รุ่นนี้ยังไม่ได้ทดสอบส่ง SMS และรายงานการรับด้วยซิมจริง

แอปส่ง SMS ผ่านซิม Android โดยนำเข้าเบอร์จาก CSV/TXT สุ่มแคปชั่นและลิงก์ แล้วส่งทีละเบอร์

## สิทธิ์ใช้งาน VisionD

ก่อนใช้แอป ให้ซื้อคีย์ VSMS จาก VisionD แล้วกรอกคีย์ในหน้าเปิดใช้งาน แพ็กเกจ 30 วัน 999 บาท หรือ 365 วัน 9,999 บาท คีย์หนึ่งชุดผูกกับเครื่องแรกที่เปิดใช้งาน ต้องให้ผู้ดูแลรีเซ็ตการผูกเครื่องก่อนย้ายไปเครื่องใหม่ แอปตรวจสิทธิ์ออนไลน์เมื่อเปิด/กลับเข้าแอป ก่อนเริ่มคิว และก่อนส่ง SMS แต่ละรายการ หากตรวจไม่ได้ คิวหยุดโดยเก็บรายการรอส่งไว้

การผูกเครื่องใช้รหัสติดตั้งร่วมกับ Android ID เพื่อป้องกันการคัดลอกข้อมูลแอปทั่วไป และ APK เผยแพร่ต้องเซ็นลายมือชื่อพร้อมเปิด R8 การป้องกันนี้ไม่สามารถรับประกันว่าระบบหรือ APK ที่ถูกดัดแปลง/รูทจะปลอมรหัสเครื่องไม่ได้ อย่านำ debug APK ไปจำหน่าย

## โฟลเดอร์ส่งมอบ

- ../apk/: APK สำหรับติดตั้งและผลตรวจไฟล์
- โฟลเดอร์นี้: ซอร์สโค้ด Android และสคริปต์ทดสอบ
- ../.tools/: เครื่องมือ build ในเครื่องพัฒนา (ไม่ใช่ส่วนของซอร์สที่ต้องนำไปใช้)

## ใช้งาน

1. ติดตั้ง APK ที่ VisionD เผยแพร่บน Android 8.0 ขึ้นไปที่รองรับ SMS แล้วกรอกคีย์
2. กดอนุญาต SMS / โหลดรายการซิม และเลือกซิม
3. เปิดสิทธิ์ตั้งเวลา (นาฬิกาปลุกและการช่วยเตือน บน Android 12 ขึ้นไป)
4. เลือกสุ่มจากไฟล์ CSV/TXT แบบ UTF-8 ขนาดไม่เกิน 2 MB (เบอร์คอลัมน์แรก) หรือใส่ช่วงเบอร์ แล้วกำหนดจำนวนที่จะสุ่ม
5. ใส่แคปชั่น 10–100 บรรทัด และลิงก์ 10–100 บรรทัด จำนวนสองชุดต่างกันได้
6. สร้างคิว ตรวจพรีวิว แล้วกดเริ่มส่งและยืนยัน
7. หยุดชั่วคราว / ทำต่อ / ส่งออกบันทึก CSV ได้จากหน้าหลัก

เบอร์แรกส่งทันทีหลังยืนยัน เบอร์ถัดไปสุ่มรอจำนวนเต็ม 10–30 นาทีจากเวลาส่งเบอร์ก่อนหน้า เลือกแคปชั่นและลิงก์แบบอิสระและสุ่มซ้ำได้ ข้อความจะถูกตรึงไว้ตอนสร้างคิวเพื่อให้ตรงกับพรีวิว การแก้ข้อความหรือเลือกซิมใหม่มีผลเมื่อสร้างคิวใหม่เท่านั้น

## ไฟล์เบอร์

ใช้คอลัมน์แรกเป็นเบอร์ มีหัวตาราง phone, phone_number, number, เบอร์ หรือ เบอร์โทร ได้ เบอร์ไทยมือถือ 06/08/09 จะเปลี่ยนเป็น +66; ต่างประเทศต้องใส่ +รหัสประเทศ รับ CSV แบบ quoted และ TXT หนึ่งเบอร์ต่อบรรทัด ตัดซ้ำหลังปรับรูปแบบ รองรับ 10,000 เบอร์ต่อคิว หากมีแถวไม่ถูกต้องจะไม่รับไฟล์ทั้งชุด และแสดงแถวที่ต้องแก้ ห้ามใช้รูปแบบเลขวิทยาศาสตร์จาก Excel

ไม่มีตัวอย่างเบอร์จริงในโปรเจกต์ เพื่อป้องกันการส่งถึงบุคคลอื่นโดยไม่ตั้งใจ

## สถานะและความต่อเนื่อง

- รอส่ง: ยังไม่ส่งให้ระบบโทรศัพท์
- รอผลจากระบบ: ส่งให้ระบบแล้ว กำลังรอ callback
- ส่งแล้ว: ทุกส่วนของ SMS ได้รับผลส่งสำเร็จจากระบบ ไม่ใช่ delivery/read receipt
- ส่งไม่สำเร็จ / บางส่วน: มีส่วนหนึ่งล้มเหลว เมื่อได้ผลครบจะรอ 5–10 นาทีแล้วไปเบอร์ถัดไป
- ไม่ทราบผล: ไม่มีผลภายใน 5 นาที หรือเกิดข้อผิดพลาดระหว่างส่ง คิวหยุดและไม่ส่งเบอร์นั้นซ้ำอัตโนมัติ

การทำต่อจะข้ามรายการที่ส่งแล้ว ล้มเหลว หรือไม่ทราบผล ส่งเฉพาะรอส่ง การสร้างคิวใหม่แทนที่คิวเก่า แต่เก็บประวัติเบอร์ที่เคยสุ่มทั้งหมดไว้ไม่ให้สุ่มซ้ำ ควรส่งออกบันทึกก่อน

คิวบันทึกแบบ atomic ก่อนส่ง SMS เพื่อหลีกเลี่ยงการส่งซ้ำหลังโปรเซสล่ม การหยุดไม่สามารถเรียกคืน SMS ที่ส่งให้ระบบแล้วได้ หลังรีบูตจะหยุดรอผู้ใช้กดทำต่อ Force-stop, ถอนสิทธิ์, เปลี่ยนเวลาเครื่อง และระบบประหยัดแบตเตอรี่ของผู้ผลิตอาจทำให้กำหนดส่งคลาดเคลื่อน ห้ามถือว่าเวลาจริงจะรับประกัน 10–30 นาทีทุกสถานการณ์

## Build

ต้องมี JDK 17, Android SDK Platform 35 และ Build Tools 35.0.0

เปิดโฟลเดอร์นี้ด้วย Android Studio หรือสร้าง local.properties ให้ชี้ SDK แล้วรัน:
    .\gradlew.bat testDebugUnitTest assembleDebug lintDebug

ไฟล์: app/build/outputs/apk/debug/app-debug.apk
สำหรับ release ให้ตั้งค่า VSMS_RELEASE_STORE_FILE, VSMS_RELEASE_STORE_PASSWORD, VSMS_RELEASE_KEY_ALIAS, VSMS_RELEASE_KEY_PASSWORD ในสภาพแวดล้อมของเครื่อง build แล้วรัน `assembleRelease` ตรวจ APK signature/certificate และ SHA-256 ก่อนอัปโหลดเผยแพร่ ห้ามเก็บรหัสผ่านหรือ keystore ใน Git หากใบเซ็นต่างจาก APK ที่ติดตั้งอยู่ จะอัปเดตทับเพื่อรักษาข้อมูลไม่ได้ ต้องสำรองข้อมูลและวางแผนย้ายเครื่องก่อน

ทดสอบ core (ไม่ใช้ Android SDK):
    .\test-core.ps1

## การตรวจบนเครื่องจริงก่อนใช้คิวเต็ม

ใช้เบอร์ที่คุณควบคุม 2–3 เบอร์ ทดสอบซิมที่เลือก, SMS ภาษาไทยหลายส่วน, ปิดหน้าจอรอช่วง 10–30 นาที, หยุด/ทำต่อ, ปิดแอป, รีบูต และกรณีไม่มีสัญญาณ ตรวจผลกับแอป SMS/โทรศัพท์ผู้รับ การทดสอบ build และ unit tests ไม่ทดแทนการทดสอบโมเด็มจริง

## ข้อมูลส่วนตัว

INTERNET permission ใช้ตรวจสิทธิ์กับ VisionD และ Shrinkrl เมื่อผู้ใช้กดสร้าง/ลองต่อ ส่งคีย์และรหัสเครื่องแบบแฮชไป VisionD แต่ไม่ส่งเบอร์โทร แคปชั่น หรือข้อความ SMS ไป VisionD ปิด Android backup สำหรับข้อมูลแอป ไฟล์ส่งออกมีเบอร์และข้อความ ควรเก็บตามความเหมาะสม

## รุ่น 0.2.0: สุ่มเบอร์ไม่ซ้ำสองโหมด

- **สุ่มจากไฟล์:** นำเข้า CSV/TXT เลือกโหมดสุ่มจากไฟล์ และใส่จำนวนที่ต้องการ (1–10,000) ระบบตัดเบอร์ซ้ำ/เบอร์ที่เคยสุ่ม แล้วสุ่มเลือกและเรียงลำดับใหม่
- **สุ่มจากช่วง:** เลือกโหมดสุ่มจากช่วง ใส่เบอร์เริ่มต้นและสิ้นสุด (รวมทั้งสองปลายช่วง) และจำนวนที่จะสุ่ม เบอร์ทั้งสองต้องมีจำนวนหลักเท่ากัน เบอร์ไทยต้องอยู่ในกลุ่ม 06, 08 หรือ 09 เดียวกัน
- ประวัติใช้ร่วมกันทุกไฟล์ ทุกช่วง และทั้งสองโหมด โดยเทียบเบอร์หลังปรับรูปแบบ เช่น 08… กับ +668… ถือเป็นเบอร์เดียวกัน
- จดจำทันทีที่สร้างคิวสำเร็จ แม้ยังไม่ได้ส่งหรือแทนที่คิวภายหลัง เบอร์เหล่านั้นจะไม่ถูกสุ่มใหม่ ปุ่ม “ทำต่อ” ใช้รายการรอส่งในคิวเดิมตามปกติ
- หากจำนวนเบอร์เหลือไม่พอ จะแจ้งจำนวนที่เหลือและไม่แทนที่คิวเดิม การกดยกเลิกแทนที่คิวไม่เพิ่มประวัติ
- เก็บคิวและประวัติในไฟล์ atomic เดียวกัน ไม่ต้องสร้างรายการทุกหมายเลขในช่วงขนาดใหญ่
- ติดตั้งอัปเดตทับแอปเดิมเพื่อเก็บข้อมูล การล้างข้อมูล/ถอนแอปจะลบประวัติ ไม่มีปุ่มล้างประวัติในแอป
- อัปเดตจาก 0.1.0 จะถือเบอร์ทั้งหมดในคิวที่ยังเก็บอยู่เป็นเบอร์เคยสุ่มแล้ว ไม่สามารถกู้ประวัติคิวเก่าที่ถูกแทนที่ไปก่อนอัปเดต
- การสุ่มช่วงเป็นการสุ่มตัวเลขตามรูปแบบ ไม่ได้ตรวจว่าเบอร์มีอยู่จริงหรือเปิดใช้งานอยู่

ข้อกำหนดเดิมยังคงอยู่: แคปชั่นและลิงก์อย่างละ 10–100, สุ่มข้อความ, ส่งผ่านซิมที่เลือก และสุ่มเว้นช่วง 10–30 นาที

ทดสอบ Android runtime และ sampler:
    .\gradlew.bat testDebugUnitTest



## รุ่น 0.3.0: บันทึกชุดแคปชั่นพร้อมชื่อ

1. ใส่แคปชั่น 10–100 รายการ บรรทัดละรายการ
2. กด “บันทึกชุดแคปชั่น / ตั้งชื่อ” ใส่ชื่อ 1–60 ตัวอักษร แล้วกดบันทึก
3. ใช้ชื่อเดิมเมื่อต้องการอัปเดตชุด โดยแอปจะถามก่อนบันทึกทับ
4. กด “เลือกชุดแคปชั่นที่บันทึกไว้” แล้วเลือกชื่อเพื่อเติมข้อความลงช่องแคปชั่น
5. หากมีข้อความอื่นในช่องอยู่ แอปจะถามก่อนแทนที่ สามารถยกเลิกเพื่อบันทึกข้อความเดิมก่อน

ชุดแคปชั่นเก็บในเครื่อง แยกจากคิวและประวัติเบอร์ จึงยังเลือกใช้ได้หลังปิด/เปิดแอป การเลือกชุดไม่เปลี่ยนลิงก์หรือข้อความในคิวที่สร้างไปแล้ว ให้สร้างคิวใหม่เมื่อต้องการใช้ข้อความชุดใหม่ ล้างข้อมูลหรือถอนแอปจะลบชุดที่เก็บไว้ด้วย


## รุ่น 0.4.0: Shrinkrl และชุดลิงก์พร้อมต้นฉบับ

1. กด “สร้างลิงก์ด้วย Shrinkrl” ใส่ URL แบบ http/https และจำนวน 1–100
2. กดสร้างลิงก์ แอปใช้ API ของ Shrinkrl สร้างลิงก์สั้นคนละรหัสที่ชี้ไปต้นฉบับเดียวกัน
3. ดูจำนวนที่ได้จริง / จำนวนที่ขอ ไม่แสดงว่าครบหากบริการคืนผลเพียงบางส่วน
4. กด “บันทึกต้นฉบับ + ลิงก์ย่อเป็นชุด” และตั้งชื่อ ชุดนี้เก็บต้นฉบับ ลิงก์ย่อทุกอันที่ได้ จำนวนที่ขอ และเวลาบันทึก
5. เลือก “ใช้ลิงก์ที่สร้างได้” เพื่อเติมลงช่องลิงก์ หรือกลับมา “เลือกชุดลิงก์ที่บันทึกไว้” ภายหลังเพื่อดูต้นฉบับและลิงก์ย่อทั้งหมด
6. ใช้ชื่อเดิมเพื่อบันทึกทับ โดยมีการยืนยันก่อน ชุดที่บันทึกเป็นผล ณ เวลานั้น หากลองต่อจนได้ลิงก์เพิ่ม ให้บันทึกทับชุดเดิมอีกครั้ง

การสร้างใหม่จะแทนผลล่าสุดในหน้าสร้าง จึงควรบันทึกเป็นชุดก่อน ชุดที่บันทึกไว้ไม่ถูกลบเมื่อสร้างงานใหม่ ปิด/เปิดแอปแล้วยังอยู่ ล้างข้อมูล/ถอนแอปจะลบชุดเหล่านี้
ผลล่าสุดและคำขอเก็บในเครื่อง หากแอปถูกปิดระหว่างสร้างให้เปิดหน้าเดิมแล้วกดลองต่อ งานนี้ไม่รับประกันว่าจะทำต่อในพื้นหลังเมื่อ Android ฆ่าโปรเซส
ปุ่มลองต่อใช้รหัสเดิม โดยดึงข้อมูลรหัสที่สร้างสำเร็จแล้วกลับมาตรวจปลายทาง การยืนยันผลไม่เปิดลิงก์ติดตามคลิก ไม่มีการวนยิงขอซ้ำอัตโนมัติ เมื่อบริการจำกัดจำนวนคำขอ/เครือข่ายล้มเหลวจะหยุดและให้ผู้ใช้ลองต่อภายหลัง

## รุ่น 0.4.1: วางลิงก์ย่อแล้วเซฟเองจากข้อ 2

ในข้อ 2 ใส่ “ลิงก์ต้นฉบับของชุดที่จะเซฟ” และวางลิงก์ย่อในช่องลิงก์ บรรทัดละรายการ จากนั้นกด “เซฟชุดลิงก์ที่วางเอง / ตั้งชื่อ” รองรับลิงก์ HTTP(S) จากบริการย่ออื่นด้วย เก็บได้ 1–100 ลิงก์ที่ไม่ซ้ำกัน และยังคงต้องมี 10–100 ลิงก์เมื่อนำไปสร้างคิว SMS

บันทึกทั้งต้นฉบับและลิงก์ย่อทั้งหมดเป็นชุดในเครื่อง ไม่เรียกบริการย่อซ้ำ ไม่ตรวจว่าลิงก์ที่วางชี้ไปต้นฉบับจริง ชื่อซ้ำต้องยืนยันก่อนบันทึกทับ เลือกชุดที่บันทึกไว้จากหน้าหลักจะเติมกลับทั้งต้นฉบับและลิงก์ย่อให้ตรงกัน ข้อมูลช่องต้นฉบับเก็บเป็นร่างหลังปิด/เปิดแอปด้วย


## รุ่น 0.4.2: ไม่ตรวจ http/https สำหรับลิงก์ที่กรอกเอง

แก้กรณีตามรูป: วางลิงก์ย่อถูกต้องแต่เว้นต้นฉบับไว้ แล้วถูกแจ้งให้ใส่ http/https
ช่องต้นฉบับของชุดที่เซฟเองเป็นช่องไม่บังคับแล้ว เซฟและโหลดชุดได้แม้ไม่มีต้นฉบับ
ลิงก์ที่วางเองและลิงก์ที่จะนำไปสร้างคิวเก็บเป็นข้อความตามที่กรอก ไม่ตรวจ scheme/host และไม่เติม http/https ให้เอง ยังคงตัดบรรทัดว่าง/ช่องว่างริมบรรทัด ตัดซ้ำตอนเซฟชุด และใช้จำนวนรายการตามเดิม
ข้อกำหนด URL ของปุ่มสร้างลิงก์ผ่าน Shrinkrl และการตรวจคำตอบจากบริการยังคงใช้เฉพาะการเชื่อมต่อบริการนั้น

- ก่อนเริ่ม อนุญาตการแจ้งเตือน และกดตั้งค่าแบตเตอรี่สำหรับส่งขณะปิดจอเพื่ออนุญาตไม่จำกัดแบตเตอรี่ บางยี่ห้อต้องเปิดอนุญาตเริ่มอัตโนมัติในตั้งค่าของเครื่องด้วย
